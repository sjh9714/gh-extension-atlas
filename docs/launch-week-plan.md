# Launch Week Plan

The goal for the first week is simple: get the atlas in front of people who already use GitHub CLI, collect corrections, and make the project easier to trust.

## Day 1: Maintainer Verification

- [ ] Contact the Top Picks maintainers listed in [`docs/outreach-targets.md`](outreach-targets.md).
- [ ] Use the maintainer verification draft from [`docs/launch-kit.md`](launch-kit.md).
- [ ] Track corrections as issues or pull requests in this repository.
- [ ] Do not ask maintainers only for stars.

## Day 2: GitHub CLI Community

- [ ] Look for the most appropriate GitHub CLI Discussion or extension-related community space.
- [ ] Share the GitHub Discussions draft from the launch kit.
- [ ] Ask for missing extensions and inaccurate descriptions.
- [ ] Reply to feedback within 24 hours.

## Day 3: Reddit

- [ ] Post to r/commandline if the rules allow project/resource sharing.
- [ ] Post to r/github only if the framing is clearly useful to GitHub users.
- [ ] Use the Reddit draft from the launch kit.
- [ ] Avoid posting identical copy in both communities at the same time.

## Day 4: Dev.to or Hashnode

- [ ] Publish the article draft from the launch kit.
- [ ] Include concrete examples of choosing between overlapping extensions.
- [ ] Link back to the comparison guides, not only the README.
- [ ] Invite corrections from extension maintainers.

## Day 5: X or LinkedIn

- [ ] Post the short social draft from the launch kit.
- [ ] Add one reply/comment with the Top Picks list.
- [ ] Add one reply/comment with the comparison guides.
- [ ] Keep the star ask restrained.

## Day 6: Feedback Pass

- [ ] Review all comments, issues, and PRs.
- [ ] Fix factual metadata first.
- [ ] Add missing extensions only when they meet the selection criteria.
- [ ] Thank contributors in issue or PR threads.

## Day 7: Maintenance Check

- [ ] Run `npm test`.
- [ ] Run `npm run summary:weekly`.
- [ ] Check current star count.
- [ ] Update issue `#1` with what worked, what did not, and the next follow-up.
