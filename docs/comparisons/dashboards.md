# Dashboard and TUI Extensions

Use this guide when you want GitHub work to feel like a focused terminal app instead of a set of disconnected commands.

| Extension                                            | Pick it when                                           | Tradeoff                                                    |
| ---------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------- |
| [gh-dash](https://github.com/dlvhdr/gh-dash)         | You need a daily PR and issue dashboard.               | It is a full TUI, so it is less suited to simple scripting. |
| [gh-lazy](https://github.com/gizmo385/gh-lazy)       | You want a compact TUI for browsing GitHub resources.  | Smaller ecosystem and fewer stars than gh-dash.             |
| [gh-eco](https://github.com/jrnxf/gh-eco)            | You want to explore profiles and ecosystem context.    | Better for discovery than operational review work.          |
| [gh-skyline](https://github.com/github/gh-skyline)   | You want a visual contribution-history artifact.       | It is more showcase than productivity tool.                 |
| [gh-graph](https://github.com/kawarimidoll/gh-graph) | You want contribution graphs directly in the terminal. | Narrowly focused on contribution visualization.             |

## Recommendation

Start with [gh-dash](https://github.com/dlvhdr/gh-dash) if your main pain is review work. Try [gh-lazy](https://github.com/gizmo385/gh-lazy) when you want a smaller exploratory TUI, and use [gh-skyline](https://github.com/github/gh-skyline) only when the output itself is the point.
